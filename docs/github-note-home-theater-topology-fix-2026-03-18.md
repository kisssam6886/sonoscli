# GitHub Note Draft — 客厅家庭影院“可入队但无法播放”问题已解决

## 摘要
这次解决的是一个现场级大坑，不是单纯的 CLI 命令问题：

- 网易云歌曲可以搜索；
- 可以成功入队；
- 但客厅播放长期卡在 `TRANSITIONING`，`RelTime=0:00:00`；
- 用户感知为“歌进去了，但播放不了”。

## 已确认不是这些原因
1. 不是旧 binary 误用导致的 Spotify ref 误判。
2. 不是网易云服务整体不可用。
3. 不是仅搜索/入队逻辑失败。
4. 不是只限于网易云，因为公开电台流在客厅也曾复现同类卡住现象。

## 真正根因
客厅是一套家庭影院绑定组，而不是单独一台设备：

- `Playbase (.31)`
- `Play:1 (.32)`
- `Sub (.33)`

现场故障时，唯一网线插在绑定成员 `Play:1 (.32)`，而不是 `Playbase (.31)`。

这导致客厅房间级 playback transport/source 状态异常，表现为：

- metadata 可见；
- 队列可写；
- 但无法稳定进入 `PLAYING`。

## 解决动作
1. 把唯一网线改插到 `Playbase (.31)`。
2. 重启网络设备。
3. 重启客厅家庭影院整组设备。

## 修复后验证
已完成客厅最小和连播验收：

1. `郑伊健 甘心替代你`
   - 可进入 `PLAYING`
   - `RelTime` 持续前进
2. 连续 `next` 后：
   - `友情岁月（电影《古惑仔之人在江湖》主题曲）`
   - `心照`
   也都进入 `PLAYING`，且时间继续前进

说明问题已从“只能入队不能播”恢复为“可连续播放”。

## 与代码问题的边界
需要明确分开两层：

### 代码层
- `ff49da0` 已修复网易云 `SONG:*` 被误当 Spotify ref 的旧逻辑。
- repo 内 `./sonos` 已支持更稳定的 queue-path 播放。

### 现场层
- 本次真正解决的是家庭影院布线拓扑错误。
- 若不改接法，只在 CLI 层反复重试，并不能稳定恢复。

## 已知注意事项
1. 固定使用 repo 内 `./sonos`，不要混用 `/opt/homebrew/bin/sonos`。
2. 唯一网线必须插在家庭影院主机 `Playbase`，不要插在绑定成员 `Play:1` 或 `Sub`。
3. 改完网线后如果一度 `discover=[]` 或 `1400` 超时，先等待或重启网络/设备，不要立刻继续点歌。
4. 不要在未稳定前频繁切 TV/music，也不要做并发补歌。

## 建议保留的稳定流程
1. `discover`
2. `mute off`
3. `queue clear`
4. 用精确查询词逐首 `smapi search ... --enqueue`
5. 第一首用 `--open` 或 `queue play 1`
6. 至少做两次 `next + status` 验收
