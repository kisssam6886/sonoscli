## 1. 项目定位（统一口径）
`sonoscli-plus` 是 Sonos 场景下的 **Agent 执行层（Execution Layer）**。

- 上层（OpenClaw / Telegram / 语音助手）负责自然语言理解
- 本仓负责稳定执行：目标房间、来源解析、队列编排、播放控制、状态恢复

一句话：
> 不是“点歌脚本”，是“可维护、可交接、可商业化”的 Sonos 控制中枢。

## 2. 商业目标（必须对齐）

### 2.1 用户体验目标
- 首次反馈：3–10 秒（先播后补）
- 连播稳定：S1/S2/S3 连续 `PLAYING`
- 故障恢复：常见播放故障 60 秒内可恢复

### 2.2 运营目标
- 规则可配置（默认房间、默认音量策略、append/replace 语义）
- 每次修复有沉淀（本地 learnings + Git commit）
- 可由其他 agent 独立执行

### 2.3 变现目标（中期）
- 免费：基础控制 + 基础播放
- 增值：高级编排、自动恢复、场景调度、语音交互、托管服务

## 3. 功能全景（你要求补齐：自然语音/TTS/不方便操作）

## A. 播放核心能力（当前主线）
1. 指定歌手播放（重建约8首）
2. 追加歌曲（加10首，不清队列）
3. 队列操作（append/replace/insert-next）
4. 播放模式（shuffle/repeat/normal）
5. 多房间控制（客厅/浴室/群组）

## B. 稳定性能力（必须产品化）
1. 播放链路健康检测（TRANSITIONING/STALLED 检测）
2. 一键修复（play -> music -> play -> status）
3. 队列去重与脏数据清洗
4. 可播性验证（入队成功 ≠ 可播成功）
5. S1/S2/S3 连播验收自动化

## C. 自然语言能力（上层接入要求）
> 虽然 NLU 不在本仓实现，但必须定义“可接入规范”。

1. 口语意图映射：
   - “播某某” => replace
   - “加10首某某” => append
   - “随机播某某” => rebuild + random start
2. 别名映射（如 Sammi/Eason/Jay）
3. 模糊纠错（同音/繁简/中英混合）
4. 多轮补全（“播歌”->默认客厅+shuffle）

## D. 语音能力（你提到：自然语音、TDS/TTS）
1. **TTS 反馈**（确认类播报）
   - 例："已帮你喺客厅播放张学友，已排8首"
2. **语音指令入口**（后续）
   - Telegram 语音 / 本地语音转文字 -> 调用执行层
3. **不方便打字场景**（驾驶/煮饭/开会中）
   - 语音短指令模板（“客厅播轻音乐”“浴室加音量”）
4. **语音失败回退**
   - 识别不清时自动给3个候选动作

## E. 不方便操作场景（你强调要写）
1. 手上有事：
   - 单句命令直达（无需多轮）
2. 夜间场景：
   - 默认低音量启动，避免突发大声
3. 家庭共享场景：
   - 指定房间/不打断当前房间
4. 弱网场景：
   - 先播可用源，后台补队列
5. 紧急静音：
   - 一句停播/静音优先级最高

## F. 自动化与调度能力
1. 定时播放（早晨/晚间）
2. 事件触发播放（到家/健身/工作开始）
3. 健康巡检（端口、状态、播放可用性）
4. 失败重试（指数退避+抖动）

## G. 运营/分析能力
1. 播放成功率、首播耗时、恢复耗时
2. 常见失败原因榜单
3. 常用艺人/场景统计
4. 可导出的日报/周报

## 4. 分阶段路线图（含验收）

## Phase 1（P0：稳定执行）
- 固化稳定 SOP
- 实现 queue dedupe
- 实现 safe append（防混入）
- 自动连播验收脚本

验收：
- 8首连播成功率 > 95%
- 平均恢复时间 < 60s

## Phase 2（P1：语音与便捷）
- 语音入口接入（STT -> 执行）
- TTS 确认播报
- 不方便操作模板（短句指令）

验收：
- 语音命令成功执行率 > 90%
- 语音反馈延迟 < 2s（文本确认）

## Phase 3（P2：商业化能力）
- 多房间编排模板
- 场景化自动播放
- 托管面板/可视化报表

验收：
- 可给第三方 agent 标准接入
- 场景任务可重复稳定运行
